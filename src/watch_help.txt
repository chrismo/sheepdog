sd watch - a pass over every enrolled branch: observe it, and with
settings.dispatch run its mechanical steps.

Usage: sd watch [refresh [<branch>] | glyph [<path>] | vacuum [--dry-run] | status | install | uninstall]

  (none)     for each repo in global git config sheepdog.repo: fetch, then
             sd state every branch with branch.<name>.sheepdog=true. Writes a
             glyph for the branch's worktree (shown by tab-status; none
             when two same-named worktrees are on one branch), notifies
             per the policy below, and records the pass. Also deletes
             refs/sheepdog/<b>/* whose branch no longer exists (pins outlive
             a branch -D), and the cached state of branches no longer
             enrolled. For one that is gone too (gh pr merge --delete-branch
             takes its enrollment), its PR's merge is notified if it wasn't.
             With settings.dispatch, also runs steps (Dispatch, below)
  refresh    the same check for one branch (default: the current one), now:
             fetch its repo, glyph, notify, cache its state. Not a pass: other
             branches and glyphs are left alone and status still shows the
             last pass. Exits non-zero when the branch couldn't be checked.
  glyph      [<path>] the glyph for the worktree holding <path> (default .),
             if it's still on the branch the last check saw; for a shell
             prompt or tab title (fast: no GitHub)
  vacuum     a pass that unenrolls every stale branch now, without waiting
             for vacuumAfter, even when it is 0, so an open PR's branch that
             no worktree holds goes too: prints each one unenrolled and its
             reason, and each one sd state is unsure of, skipped, and why.
             It doesn't notify its own unenrolls. It also prints each
             branch file it deletes (see Branch files below).
             --dry-run: what vacuum would do, judged from each branch's last
             saved check (one where sd state failed isn't saved; nothing is
             fetched or changed), and when a pass would unenroll it
  status     print the last pass
  install    launchd job: a pass every settings.interval seconds (default 300)
  uninstall  remove the job

Glyphs: ❌ needs chrismo   ⚠️ state unknown   🔧 work for later   ⏳ waiting (CI, review)
        ✅ ready to merge  🏁 merged          🚫 closed           🤖 an agent step running

Notified, once per NEXT step (src/next.rs) entered (again only after it clears):
  ci-red ci-blocked conflict human foreign parent-closed restack-undone: ❌ the
    PR is stuck or wrong
    until chrismo, or an agent chrismo starts, deals with it
  bot-silent: ❌ the review bot hasn't answered within settings.botTimeout
  merged ready: chrismo acts (clean up, merge)
  review-decide: ❌ the local review still blocks after
    settings.reviewRounds rounds, or the agent declined its findings:
    chrismo fixes them or accepts HEAD
  question: ❌ an agent step needs chrismo's answer, or gave up (#254), and
    nothing reruns it until chrismo answers, edits or acks (#167); a
    restack --resolve that gave up reruns once its target moves (#257)
  budget: ❌ the branch's steps have spent past settings.branchBudget, so
    no agent step runs on it until chrismo raises it or takes over
  failed: ❌ 3 agent steps failed in a row (a harness or provider down?),
    so none runs until chrismo fixes it and reruns the last one (#242)
  ci-config: ❌ an agent step's commit changed CI config, held unpushed
    until chrismo reviews it and runs sd act push (#124)
  nothing default: ❌ nothing ahead of the base and no task to implement, or
    the default branch itself: chrismo commits, records a task, or starts a
    branch (#143, #159)
  dirty: ❌ uncommitted edits hold up an agent or restack step that refuses
    them, and nothing says whose they are: chrismo's hand edit, or an agent
    step's that failed or timed out (#178). The
    two steps below are the same edits where the state says they're
    chrismo's, so those aren't notified
  read: ❌ info-only bot items, shown once nothing else moves without
    chrismo: unnotified, an unattended loop stalls there unseen (#76)
  submit yours: ❌ a followed PR (sd act follow, #250) is chrismo's turn:
    the review of HEAD is theirs to submit on GitHub, or the branch has
    commits the PR doesn't
Not notified:
  closed: chrismo closed it
  errors stale gh-wait: ⚠️ sd state can't be sure, so what was notified
    carries over; gh-wait is GitHub not yet showing a push (#246)
  reset-dirty take: chrismo is mid-change on the branch: no sheepdog step
    resets pushed commits away, so the reset and the edits with it are
    chrismo's; the 🔧 glyph shows it
  nothing-dirty: the same, on a branch chrismo hasn't committed to yet (an
    agent step's edits show as running instead)
  running: an agent step is running on the branch (#170); what was notified
    carries over, since it hides every other step
  blocked: GitHub's branch rules, often routine; the 🔧 glyph shows it
  attached: chrismo is in the branch's session; like merge-wait, keeps ready
  bot: routine agent work, picked up when the branch is next worked on
  review review-fix implement: the same
  behind push open-pr ship-parent draft bot-trigger ci-rerun retarget: mechanical
    (behind with no old base is chrismo's, but its errors step shows ⚠️ first)
  ci-wait bot-wait review-wait parent-wait merge-wait: waiting; merge-wait (GitHub
    recomputing after the base moved) keeps ready notified
  fetch author-wait: a followed PR's (#250): the author pushed, mechanical
    to take; or chrismo's review of HEAD is in, and it's the author's turn
A notification that fails is tried once more, on the next pass that still
shows its step, then given up on.

Stale enrollments: a pass unenrolls a branch (git config only; never the
branch, its pins, a worktree or a PR) with no local branch at once, and one
merged, closed or checked out nowhere once it has been so for
settings.vacuumAfter seconds (default 7 days; 0 turns off these three). A
pass whose sd state reported errors or stale data neither starts, resets nor
acts on that clock, and a new reason restarts it. Each timed unenroll
notifies, once; one for no local branch is only a pass line. sd watch vacuum
doesn't wait for the clock, vacuumAfter 0 included, but counts only these
reasons and skips a branch sd state is unsure of, as a pass does.

Branch files (#283): each pass deletes, in every registered repo, the files
in $GIT_COMMON_DIR/sheepdog that no local branch owns: a branch's sd config
file (<branch>.json) and its stored description (<branch>.describe.json),
which a branch -D leaves behind. A branch that exists keeps both, enrolled
or not. Only vacuum prints them; vacuum --dry-run lists them.

Dispatch (#267): off unless settings.dispatch is true (sd config set
--global --json settings.dispatch true); branch.<b>.sd-dispatch false turns
it off for one branch. A pass then launches a branch's first NEXT step when
it is one of these run steps, as sd act <verb> <branch> from the repo: fetch,
behind (restack), push, retarget, bot-trigger (trigger). One attempt per
branch per pass, under SHEEPDOG_WATCH_TIMEOUT; the next pass sees what it
did. Only on a PR the viewer (gh's login) authored with no one else's
commits on the remote: none this copy never had, none taken and reset away.
fetch, a followed PR's, runs whoever wrote the PR: it refuses when the
branch has commits of chrismo's. Not while sd state reports errors or is
unsure, an agent step runs or the session is attached, or after the rate
limit stops the pass; never on refresh or vacuum.
The other run steps (stale: the pass just fetched; merged, draft, ci-rerun,
ship-parent, open-pr) and every agent step stay chrismo's.

Launched steps (#268): the pass doesn't wait for one. It runs as sd watch
step <secs> <verb> <branch>, in a session of its own (launchd's cleanup of
the job never signals it), holding the branch's running marker as a lease:
the marker's second line, deadline <time>, is the step's timeout plus 60s.
Its output goes to steps.log in SHEEPDOG_STATE_DIR. The pass's line, also
in status, is launched sd act <verb>; the next pass reports how it ended:
ran sd act <verb>: ok, failed (exit <n>): <its last line>, timed out after
<n>s, or stopped by a signal. Each pass first reconciles every branch's
lease: one past its deadline gets TERM to its process group, KILL 5s later
if it's still there; one whose process is gone with no outcome crashed.
Either counts in the failure record (refs/sheepdog/<b>/failed, harness sd),
as a launched step that timed out does. A marker with no deadline, a step
chrismo ran, is never ended or counted.

GitHub's rate limit: a pass checks no more branches after one whose sd
state found less than settings.rateLimitFloor GraphQL points left (default
250), or had a call refused for the rate limit. Status says so with the
reset time, and lists each branch not checked; those keep their glyphs and
cached state. The housekeeping that asks GitHub's GraphQL nothing still
runs. refresh checks its one branch either way.

Env:    SHEEPDOG_STATE_DIR (~/.local/state/sheepdog), STATUS_DIR (~/.claude/tab-status)
        LOCAL_BIN (~/.local/bin): where install finds the sd link the job runs
        SHEEPDOG_WATCH_TIMEOUT (120): seconds a fetch, sd state or a
        dispatched step may take
Config: read as sd config does, no branch file (global file over
        built-in defaults): settings.notify, .interval, .remote, .vacuumAfter,
        .rateLimitFloor, .dispatch. .remote is read from inside each repo, so that
        repo's file (sd config set --repo) can set it.
        notify — shell command, run with <title> <message> appended
        (default: a macOS notification)
