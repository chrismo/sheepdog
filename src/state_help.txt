sd state - where a branch's PR stands.

Usage: sd state [--json | --long] [<branch>]

Reports, for <branch> (default: the current one):
  task      the recorded task (branch.<b>.sd-task), else null
  mode      reviewer for a teammate's PR followed with sd act follow
            (branch.<b>.sd-mode), else null (#250). Its PR is the stored
            number alone, never discovered; its push block compares HEAD to
            the PR's head as fetched (refs/sheepdog/<b>/pr-head), never
            judged ours or theirs, and push.author_pushed says GitHub's head
            is past it; and NEXT has a list of its own: fetch the
            author's pushes, review, then chrismo submits on GitHub
  pr        the branch's PR (an open one wins over closed/merged);
            pr.author is its author's login
  viewer    the GitHub login gh runs as; null when gh fails
  parent    sd-parent config, else the PR base, else the default branch;
            whether it exists here and on the remote (a parent only here
            has to ship first);
            a merged parent retargets sync to the default branch
  sync      ahead of / behind the parent? would `rebase --onto` conflict?
            sync.replays_parent: after a merged parent, its PR's commits
            in old_base..HEAD, newest first: a wrong base, which sd act
            restack refuses unless it goes by tree; [] otherwise, null
            when git can't list them
            sync.foreign_authors, sync.foreign_commits: as push's below,
            for the commits a restack would rewrite (old_base..HEAD, past
            the target) while it's behind: sd act restack refuses them
            unless --force, which adds them to branch.<b>.sd-authors-seen
            too, so the push that follows isn't held for them (#356)
  push      local vs remote branch; whether the remote SHA is ours (reflog),
            and for a remote ahead of a reset: whether those commits were
            made here and whether the worktree has uncommitted changes;
            held: an agent step's unpushed change to CI config (sd act's
            hold), {sha, paths}, else null
            push.foreign_authors: the author and committer emails other
            than user.email on the commits sd act push would remove from
            the remote (diverged, or dropping commits reset away; past
            HEAD, the target, the base and the default branch), newest
            first, leaving out those already looked at and those whose
            patch is on the target (squash-merged alone). GitHub's
            noreply@github.com committer (a web edit, Update branch, a
            suggestion) counts as its author: ours when that's user.email
            or the viewer's users.noreply.github.com address, never named.
            Without the viewer (gh failed), a noreply address counts as
            someone else's: the push holds rather than guess. sd act push
            refuses them unless --force (#356).
            [] when there are none, null when user.email is unset, git
            can't list them, or the branch is a followed PR
            push.foreign_commits: those commits' ids, each its patch-id (or
            its SHA with no diff); sd act push --force adds them to
            branch.<b>.sd-authors-seen, the looked-at ones, and a patch-id
            outlives a restack
  ci        checks on the PR head commit. Only each check's latest run counts
            (by app, workflow, event and name): a rerun or a new run on the
            same SHA, say from an edited title, supersedes the old one
            (#195). A check that didn't start or wants approval
            (STARTUP_FAILURE, ACTION_REQUIRED) is blocked, chrismo's, not
            red. For a draft, also the base branch's required checks
            (rulesets and classic protection; matched by name, not app):
            one with no context on the head is missing,
            and keeps the verdict pending, so undraft waits for it (#123).
            One that never runs on a draft (a workflow skipping drafts, or
            filtered to other branches, for a stacked draft) waits forever:
            no timeout, since nothing here says how long it has been
            missing; the wait step says to undraft by hand instead.
            A non-draft doesn't need them: GitHub's merge state counts them
  review    coverage of HEAD by refs/sheepdog/<branch>/{local,bot,accepted};
            a pin's <kind>-base ref is the base it was taken against, so a
            restack doesn't make a reviewed change look changed
            review.findings: sd act review's open findings
            (refs/sheepdog/<b>/findings), counting those that block, and
            whether they're about HEAD (the same commit, or the same change
            rebased)
            review.bot also has triggered (when sd act trigger posted, by
            GitHub's clock), replied (a bot has posted since; null with no
            trigger time or when gh fails) and waited (seconds since)
            review.accepted also has after (the bot's triggered when sd act
            review --accept pinned it; null with no trigger then, or for a
            pin made by hand)
            review.github, for a followed PR: the viewer's last submitted
            verdict (approved, changes requested, or commented with a
            top-level body; a lone inline comment or thread reply isn't
            one), {sha (the commit it reviewed), state, at_head, pending
            (one is pending too)}; null with none, or when gh fails
  question  an agent step's needs-input, or its give-up (kind gave-up,
            else ask; #254) (refs/sheepdog/<b>/question, see
            sd act ack): {step, kind, sha, text, at_head}; at_head while HEAD and
            the worktree's uncommitted state are what the step left (and,
            for resolve's, the target it rebased onto, #257), and
            then NEXT's question step replaces the step that asked (#167)
  flags     for chrismo, never a gate (#125): in the net diff old_base..HEAD
            (the whole branch, whoever wrote it), added lines matching
            settings.flags.suppressions, added skips (settings.flags.skips)
            in test files, and each hunk of changed or deleted lines in a
            test file the base had, or a test file renamed out of the test
            files (test-edit); with the commit that added
            the line (blame), or for a test-edit the commits that touched
            the file. Test files: settings.flags.testFiles, globs on the
            file's name, a whole path when one has a /, or a directory
            anywhere when it ends in /. null without a base, or when the
            check fails or can't run (an invalid pattern, an unreadable
            diff, a tree base that isn't HEAD's ancestor); then
            flags_error says why, kept out of errors so NEXT ignores it
  threads   what's owed, marked ! (blocks: unresolved threads, reviews
            requesting changes) or i (to read: bot review bodies and PR
            comments not yet marked handled)
  bot       the review bot's trigger comment (settings.botCommand), if any,
            and timeout (settings.botTimeout)
  session   pipeline enrollment, harness, session id, takeover lock;
            profile: the config profile pick in effect (sd config's
            profile: the branch file's, else the repo file's), a name or a
            list, else null; the one-liner names it (#293);
            running: the agent step running on the branch, {step, pid,
            since}, from its running marker (src/running.rs), else
            null. While it runs,
            NEXT is only to wait for it (#170)
  spend     usd: what the branch's agent steps have cost in this repo, by
            the usage record (usage.sup, src/usage.rs); unknown: the steps
            whose cost isn't known (cost_usd null: stopped by a signal, or
            killed with no cap, after a billed turn), {time, step, session}
            each; both since sd act forget last reset it; budget:
            settings.branchBudget (USD, 25; 0 is none). Past it, or with a
            step of unknown cost, NEXT hands the agent's steps to chrismo
            (#121, #349)
  failed    agent steps that failed (or returned nothing usable) in a row
            on the branch (refs/sheepdog/<b>/failed): {step, harness,
            count, since, at, error}, the last one's; a step that succeeds
            removes it. After 3, NEXT hands the agent's steps to chrismo
            (#242)
  verify    the last failed settings.verify (refs/sheepdog/<b>/verify-red):
            {sha (the commit it ran on), step (the verb that ran it), cmd,
            at, at_head}; a pass removes it, null with none. While at_head,
            NEXT's verify-red step stands in for push, open-pr, draft,
            review, bot-trigger and ready, and sd act ship refuses (#325)
  fresh     false when GitHub's PR / parent-PR head differs from the local
            remote-tracking ref and isn't an older value of it (see lag),
            i.e. sync and push answers need a fetch;
            or, when NEXT's first step would be ready alone (#169), an
            agent step, open-pr or bot-trigger (#182), or blocked alone
            on GitHub's DIRTY (#246), when the remote's base branch (by
            ls-remote; with no PR, sync.target) does
  stale     why fresh is false
  lag       GitHub's PR / parent-PR head that is an older value of the
            remote-tracking ref (its ancestor, or in its reflog): GitHub
            hasn't seen a push yet, so that isn't stale, and NEXT waits
            (#246)
  stored    what sheepdog keeps for the branch: handled ids, refs/sheepdog/<b>/*
  rate_limit  GitHub's GraphQL quota: cost (this run's calls, summed),
            remaining and reset_at (the last call's; null when none
            answered), limited (a call was refused for the rate limit)
  next      what to do, in order: {key, who, say, cmd} (src/next.rs)

Output:
  default   the one-liner (led by the PR's url, not the branch), then NEXT:
            the first step and how many follow
  --long    the one-liner, every step, then a line per owed item
            (mark, type, author, excerpt, url), per open review finding
            (r, severity, file:line, body) and per flag (⚑, kind,
            file:line, the line, commits)
  --json    everything

Never fetches, and writes only the PR numbers it finds (branch.<b>.sd-pr,
the parent's too), when they change, and removes a running marker whose
pid is gone or now another process's (#177). The PR numbers make it a
.git/config writer:
while it holds config.lock, another git config write fails. Remote refs
are as fresh as the last fetch, except the PR's base (or, with no PR, the
target) when NEXT's first step is ready alone, an agent step, open-pr,
bot-trigger, or blocked alone on DIRTY (GitHub sees a conflict the local
refs don't): one git ls-remote of it, 10 s at most, and no check on a
failure (#169, #182, #246).
One gh GraphQL call per PR (the branch's,
and a non-default parent's), by its stored number; a discovery by branch
comes first for a PR not yet known, and is the only call for a branch with
none. A stored PR that merged stays the branch's PR, even once a newer one
is open from the same branch: the branch is done (#122). Only a local
branch stores a number, so a parent that isn't one, or a fresh clone, gets
discovery's pick (an open PR first); git config --unset branch.<b>.sd-pr
makes sd state look again. A followed branch's number (sd-mode
reviewer), as the branch or as a parent, is its record: never discovered,
never unset (#339). A draft adds two REST calls, for its base
branch's required checks. A gh failure is
recorded in .errors and the git facts are still reported.

Config: read with sd config (branch file over repo file over global file
over built-in defaults), under settings: remote (origin; gh is asked about
its GitHub repo, see sd config --help), botLogin (bots that post as users,
counted as bots; a [bot] suffix is optional), botIgnore (bots whose posts
are never owed, e.g. github-actions preview links), botIgnoreBody (regexes:
bot reviews and PR comments whose body matches are never owed).
Either also keeps a bot's post from counting as the review bot's reply
after sd act trigger: any other bot's post does, so a CI or preview bot
that comments after a push belongs in one of them. So a botIgnoreBody
pattern must not match the review bot's own verdict (a clean "No issues
found" included), or that verdict never ends the wait. A reply is a new
review or comment: a bot that edits one sticky comment in place isn't seen,
and runs into bot-silent. Nor is the commit checked: a slow reply to an earlier
trigger that lands after a later one counts as the later one's reply.
botTimeout (seconds, 3600): how long to wait on that reply before
bot-silent. flags: {suppressions, skips} (RE2 regexes over a line's text)
and testFiles (globs); a list set in a file replaces that list's default,
and [] turns it off.
State: branch.<name>.pr-{parent,tend,harness,session,lock}, branch.<name>.sd-pr
(the PR's number, written here), branch.<name>.sd-handled
(multi-valued: node ids of bot reviews/comments already dealt with),
branch.<name>.sd-unposted (multi-valued: the owed items of an address round
whose replies didn't post, a thread as <id>@<its last comment's id>;
threads.unposted),
branch.<name>.sd-bot-triggered (when sd act trigger posted its comment),
branch.<name>.sd-accepted-after (the sd-bot-triggered sd act review --accept followed).
